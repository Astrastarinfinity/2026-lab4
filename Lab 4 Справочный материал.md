# Справочно-методический материал к лабораторной работе «STP»

## 1. Основы STP

### 1.1. Зачем нужен STP
В сети L2 резервные линки образуют петли. Петля приводит к бесконечной пересылке широковещательных кадров (broadcast storm), нестабильности таблицы MAC и дублированию кадров. STP логически блокирует часть портов, превращая физически закольцованную топологию в дерево без петель, сохраняя при этом резервирование.

### 1.2. Роли и состояния портов

| Роль | Смысл |
|---|---|
| **Root Bridge (корневой мост)** | Логический центр дерева. Один на VLAN. Выбирается по наименьшему **Bridge ID** |
| **Root Port (корневой порт)** | На некорневом мосте — порт с **наименьшей стоимостью пути** до корня. Один на некорневой мост (на VLAN) |
| **Designated Port (назначенный порт)** | Порт на каждом сегменте, отвечающий за пересылку трафика этого VLAN. На корневом мосте все порты — назначенные |
| **Blocked / Alternate** | Ни корневой, ни назначенный — блокируется для предотвращения петли |

Состояния классического 802.1D: `Blocking` → `Listening` → `Learning` → `Forwarding` (сходимость ~30–50 с). Rapid PVST+ (802.1w) упрощает до `Discarding` → `Learning` → `Forwarding`, сходимость — секунды.

### 1.3. Состав Bridge ID

Bridge ID = **Bridge Priority (2 байта)** + **Extended System ID (VLAN ID, 12 бит)** + **MAC-адрес коммутатора (6 байт)**

- Приоритет по умолчанию — **32768**.
- Поскольку Extended System ID содержит VLAN ID, Bridge ID одной и той же машины в разных VLAN различается — это основа **per-VLAN STP** в PVST+ / Rapid PVST+.
- Приоритет настраивается в диапазоне **0–61440** с шагом **4096** (допустимые значения: 0, 4096, 8192, …, 61440).

## 2. Правила выборов (корень, корневой порт, назначенный порт)

### 2.1. Выбор корневого моста
Все коммутаторы изначально считают себя корнем. После получения BPDU соседа сравниваются **Bridge ID**, **наименьший побеждает**. Порядок сравнения:

1. Сначала **Bridge Priority** (меньше — лучше)
2. При равенстве приоритетов — **MAC-адрес** (меньше — лучше)

> **Важно**: из-за Extended System ID при сравнении Bridge ID фактически сначала сравнивается связка `Priority + VLAN ID`. В пределах одного VLAN часть VLAN одинакова, поэтому реально сравниваются настроенные приоритеты.

### 2.2. Выбор корневого порта (на некорневом мосте)
Для каждого некорневого моста среди всех **неназначенных** портов выбирается «ближайший» к корню. Порядок сравнения:

1. **Root Path Cost (накопленная стоимость до корня)** — наименьшая
2. При равенстве — **Bridge ID вышестоящего (соседнего) коммутатора** — наименьший
3. При равенстве — **Port ID вышестоящего** — наименьший (Port ID = Port Priority + номер порта; по умолчанию Port Priority 128)
4. При равенстве — **локальный Port ID** — наименьший

### 2.3. Выбор назначенного порта (на каждом сегменте)
На каждом сегменте сравниваются BPDU, отправленные с обоих концов:

1. Побеждает сторона с меньшим **Root Path Cost** отправителя
2. При равенстве — меньший **Bridge ID** отправителя
3. При равенстве — меньший **Port ID** отправителя (Port Priority + номер)

Победивший порт становится назначенным (Forwarding), противоположный — неназначенным (Blocking / Alternate).

## 3. Режимы STP и настройка

### 3.1. Просмотр и переключение режима

```text
Switch# show spanning-tree summary
Switch(config)# spanning-tree mode rapid-pvst
```

Режим по умолчанию зависит от платформы. У 2960 в новых версиях Packet Tracer / IOS по умолчанию может быть уже `rapid-pvst`; если по умолчанию `pvst`, в верхней части вывода `show spanning-tree summary` будет указан текущий режим. После смены режима все VLAN пересобирают дерево.

### 3.2. Принудительное назначение корня

```text
Switch(config)# spanning-tree vlan 10 root primary
Switch(config)# spanning-tree vlan 10 root secondary
```

- `root primary`: устанавливает приоритет **24576** (если этого недостаточно для становления корнем, IOS автоматически понижает до ближайшего допустимого значения).
- `root secondary`: устанавливает **28672** — резервный корень.
- Можно задать приоритет вручную для точного контроля:

```text
Switch(config)# spanning-tree vlan 10 priority 16384
```

## 4. Управление выбором корневого порта: Port Priority и Port Cost

### 4.1. Изменение приоритета порта (Port Priority)

Назначение: настраивается на порту **вышестоящего** коммутатора и влияет на выбор корневого порта **нижестоящим** коммутатором на третьем уровне сравнения (Port ID вышестоящего).

```text
Switch(config)# interface Fa0/2
Switch(config-if)# spanning-tree vlan 10 port-priority 112
```

Допустимые значения **0–240** с шагом **16**: 0, 16, 32, 48, 64, 80, 96, 112, 128, 144, 160, 176, 192, 208, 224, 240. По умолчанию **128**, **меньше — лучше**.

> **Не путать с `switchport priority`**. `switchport priority` — это CoS для QoS, к STP отношения не имеет. Ключевое слово для приоритета порта в STP — **`spanning-tree vlan <id> port-priority <значение>`**.

### 4.2. Изменение стоимости порта (Port Cost)

Назначение: настраивается на порту **нижестоящего** коммутатора и напрямую влияет на **накопленную стоимость пути** до корня.

```text
Switch(config)# interface Fa0/3
Switch(config-if)# spanning-tree vlan 20 cost 10
```

Чем меньше cost, тем «охотнее» порт становится корневым.

### 4.3. Разница между двумя приоритетами (частая путаница)

| Команда | Где настраивается | На кого влияет | Место в порядке сравнения |
|---|---|---|---|
| `spanning-tree vlan X port-priority Y` | Порт вышестоящего коммутатора | Выбор корневого порта нижестоящим | 3-й уровень (Port ID вышестоящего) |
| `spanning-tree vlan X cost Y` | Собственный порт | Собственный выбор корневого порта | 1-й уровень (Root Path Cost) |

## 5. PortFast, BPDU Guard, Root Guard

### 5.1. PortFast
На access-порту (к PC, серверу, принтеру) PortFast при поднятии линка сразу переводит порт в Forwarding, пропуская Listening/Learning и избавляя терминал от ожидания ~30 секунд.

```text
Switch(config)# interface Fa0/10
Switch(config-if)# spanning-tree portfast
```

**Проверка**: в выводе `show spanning-tree interface Fa0/10 detail` будет строка `Portfast: Enabled`. `show spanning-tree interface Fa0/10` (без `detail`) **не показывает** состояние PortFast.

**PortFast на trunk-порту**:

```text
Switch(config-if)# spanning-tree portfast trunk
```

Только для trunk-портов, где **заведомо нет коммутатора** на другом конце (router-on-a-stick, trunk-адаптер сервера). **Строго нельзя** на trunk-порту, соединяющем коммутаторы, — иначе можно обойти расчёт STP и получить петлю.

### 5.2. BPDU Guard
Если на access-порту с PortFast **не должно** приходить BPDU (на другом конце терминал, а не коммутатор), то при получении BPDU BPDU Guard немедленно переводит порт в **err-disabled**.

```text
Switch(config)# interface Fa0/4
Switch(config-if)# spanning-tree bpduguard enable
```

### 5.3. Root Guard
Root Guard настраивается на порту в направлении, где **не должен появиться корень**. Если на этот порт приходит **более выгодный BPDU** (сосед заявляет, что он больше подходит на роль корня), Root Guard не выключает порт, а переводит его в **root-inconsistent** (блокировка на уровне STP), не давая порту участвовать в выборах корня.

```text
Switch(config)# interface Fa0/5
Switch(config-if)# spanning-tree guard root
```

**Проверка**: `show spanning-tree inconsistentports` перечислит порты, заблокированные Root Guard.

**Ключевое отличие от BPDU Guard**:

| | BPDU Guard | Root Guard |
|---|---|---|
| Условие срабатывания | PortFast-порт получает **любой** BPDU | Порт получает **более выгодный** BPDU (сосед хочет стать корнем) |
| Состояние порта | `err-disabled` (административно выключен) | `root-inconsistent` (блокировка STP) |
| Восстановление | Вручную `shutdown`/`no shutdown` | **Автоматически** после прекращения более выгодных BPDU |
| Типичное применение | Защита портов доступа к терминалам | Защита позиции корня от захвата периферийным коммутатором |

## 6. Шпаргалка команд проверки

| Задача | Команда |
|---|---|
| STP по всем VLAN | `show spanning-tree` |
| STP по конкретному VLAN | `show spanning-tree vlan <id>` |

| Информация о корневом мосте | `show spanning-tree root` |
| Корневой мост конкретного VLAN | `show spanning-tree vlan <id> root` |

## 7. Типичные явления и их объяснение

1. **Кто корень при STP по умолчанию?** Все приоритеты 32768, побеждает коммутатор с наименьшим MAC — обычно тот, что стартовал первым или имеет наименьший MAC.
2. **Почему при равных линках работает только один?** Все линки равны по cost и соседу, STP выбирает один корневой порт (наименьший Port ID вышестоящего), остальные блокируются. Это нормально.
3. **Почему после изменения port-priority корневым становится другой порт?** Меньший port-priority на вышестоящем коммутаторе выигрывает по Port ID, и нижестоящий коммутатор выбирает соответствующий порт корневым.
4. **Почему после уменьшения cost корневым становится порт с малым cost?** Малый cost напрямую выигрывает по Root Path Cost.
5. **Почему коммутатор с малым приоритетом не отбирает роль корня?** Если на порту в его сторону настроен Root Guard, более выгодный BPDU перехватывается, порт уходит в root-inconsistent, и этот коммутатор не может через данный порт повлиять на выборы корня.
6. **Почему порт с BPDU Guard уходит в err-disabled?** На порту настроен BPDU Guard (и порт — access), при получении BPDU срабатывает защита, порт административно выключается. Нужно восстанавливать вручную.

## 8. Частые ошибки

1. **`show spanning-tree interface` без `detail` не показывает PortFast** — состояние PortFast есть только в выводе с `detail`.
2. **Путают `switchport priority` с приоритетом порта STP** — первое это CoS для QoS, для STP нужен `spanning-tree vlan X port-priority`.
3. **PortFast на порту между коммутаторами** — может привести к петле; на межкоммутаторных портах PortFast не настраивают.
4. **BPDU Guard на порту между коммутаторами** — при первом же BPDU порт уйдёт в err-disabled, линк упадёт.
5. **Путают Root Guard и BPDU Guard** — первый защищает от захвата корня, второй — от подключения коммутатора к терминальному порту. Один восстанавливается автоматически, другой — вручную.
6. **Изменили приоритет, но забыли `write`** — после перезапуска Packet Tracer конфигурация теряется.
7. **Переключили режим STP и сразу смотрите результат, не дождавшись сходимости** — Rapid PVST+ сходится быстро, но в момент переключения состояние может быть нестабильным, подождите несколько секунд и снова выполните `show`.
